## 二、架构设计验证点（数据流）

- **先审后发闭环**：提交 → pending（关键词/频控打标）→ 审核通过 → `comment.approved` 事件 → 缓存失效 + `comment_count+1` → 前台立即可见 ✅
- **发布流水线**：同步接口只返回 `taskId`，异步 worker 执行 5 步状态机，前端可轮询 `/tasks/:id` ✅
- **统计聚合**：`POST /api/events` 落库 + 事件队列 → `analytics_daily` 聚合 → 看板趋势/Top5 零实时计算 ✅
- **限流语义**：搜索 42901 拒绝；评论频控不拒绝、打标「频率限制」转人工审核（与架构 §6.3 一致） ✅
- **幂等**：`Idempotency-Key` 重复提交返回同一评论 ID ✅

## 三、测试中发现并已修复的问题

| # | 问题 | 根因 | 修复 |
|---|---|---|---|
| 1 | 服务启动失败 `RuntimeError: Directory uploads does not exist` | StaticFiles 装配期校验目录，但目录在 lifespan 才创建 | `main.py` 挂载前先 `mkdir` |
| 2 | 种子导入失败 `sqlite3.OperationalError: 4 values for 5 columns` | `analytics_daily` INSERT 占位符数量错误 | `db.py` 补第 5 个 `?` |
| 3 | `/api/taxonomy` 500 `no such column: t.tag_id` | 标签统计 JOIN 条件笔误 | `routers_public.py` 改为 `pt.tag_id=t.id`，并将计数改为 `COUNT(p.id)`（只统计已发布文章） |
| 4 | `/api/search?sort=latest` 500 `'tuple' object is not callable` | 排序 lambda 后多余逗号使 key 成为元组 | 改为显式 if/else 排序 |
| 5 | TOTP ticket 可重放（安全缺陷） | 动态码格式校验在消费票据之前，失败尝试不消耗票据 | `routers_auth.py` 调整顺序：先消费票据再校验，票据一次性 |
| 6 | 审核通过 500 `NameError: publish_event` | `routers_admin.py` 漏导入 | 补充导入 |

## 四、遗留说明（非缺陷）

- 密码哈希使用 stdlib PBKDF2（26 万次迭代），生产建议按架构文档换 Argon2id；
- 缓存/限流/事件队列为进程内实现，接口与事件契约已按生产形态设计，切换 Redis/RabbitMQ 不改业务代码；
- 搜索为 SQL LIKE 实现，响应契约（`<mark>` 高亮、排序）与 ES 方案一致，P3 阶段无缝替换。
